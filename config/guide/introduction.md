# 简介

## 什么是 TierFlow？

TierFlow 是面向智能体时代的 LLM Token 优化与智能调度平台。它通过统一的 OpenAI 兼容 API 接入多模型、多供应商能力，并由自研 BrainNet-8B 任务感知引擎在每个 step 分析任务意图、上下文、复杂度、模型能力、成本与可用性，动态选择最合适的模型和执行路径。

对开发者来说，TierFlow 的接入方式保持简单：已有 OpenAI SDK 调用只需要替换 `base_url`，并把模型名设置为 `auto`。后续的模型选择、上下文压缩、重试和成本控制由 TierFlow 负责。

下面是一个最简单的接入示例：

```python
from openai import OpenAI

client = OpenAI(
    api_key="your-tierflow-key",
    base_url="https://api.tierflow.ai/v1"
)

response = client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "你好"}]
)
```

上面的代码展示了 TierFlow 的两个核心特性：

- **统一接口**：兼容 OpenAI SDK，已有代码只需替换 `base_url` 即可接入。
- **智能路由**：`model="auto"` 让 TierFlow 根据任务阶段、上下文和成本约束自动匹配模型。

> 已经熟悉这些概念？可以直接跳到 [快速开始](/guide/getting-started)。

## 核心问题

在生产级 AI 应用和智能体任务中，开发者通常会遇到这些问题：

- **Token 成本不可控**：复杂任务链会消耗大量上下文，全部交给旗舰模型会快速推高成本。
- **模型选择成本高**：不同 step 对推理、代码、检索、总结和工具调用的要求不同，手动选择模型很难持续维护。
- **上下文冗余**：多轮任务中存在大量无效或重复上下文，直接传递会增加延迟和费用。
- **供应商可用性风险**：单一模型或单一供应商出现限流、故障或价格变化时，业务稳定性会受到影响。

TierFlow 的目标是在不牺牲输出质量的前提下，让每一次模型调用都更合适、更稳定、更低成本。

## 智能路由平台

TierFlow 的核心是 BrainNet-8B 类脑任务感知模型。它不是简单的固定规则分发，而是在每个任务 step 中综合判断当前请求需要什么能力、应该保留哪些上下文、适合调用哪个模型，以及如何在质量、速度和成本之间取得平衡。

你可以把 TierFlow 用作：

- OpenAI API 的兼容入口，用最小改造接入自动路由能力。
- 多模型网关，统一管理不同供应商、模型和额度。
- 智能体调度层，按 step 匹配模型能力和执行路径。
- 高可用推理入口，在故障、限流或成本变化时自动切换备用路径。

无论是哪种用法，核心链路都是一致的：**感知任务 -> 精炼上下文 -> 匹配模型 -> 路由执行**。

## 路由决策

BrainNet-8B 会把一次请求拆解为可判断的路由信号，再合成为单次 step 的决策：

- **任务理解**：识别用户意图、目标约束、工具需求和关键输入。
- **复杂度评估**：判断当前 step 是否需要高能力模型，还是轻量模型即可完成。
- **上下文压缩**：提取核心上下文，减少无效 Token 消耗。
- **模型能力映射**：匹配不同模型在代码、推理、总结、工具调用等场景中的优势。
- **成本预测**：把预算、延迟、成功率和模型价格纳入同一次选择。
- **决策输出**：生成最合适的模型、供应商和执行路径。

## 适用场景

TierFlow 特别适合需要持续调用大模型 API 的应用：

- **AI Agent**：多 step 任务中，不同阶段可以分别路由到不同等级的模型。
- **SaaS 产品**：高频请求中包含大量简单任务，可以在保证质量的同时降低平均成本。
- **开发者工具**：代码解释、修复、测试生成和文档总结可以按任务难度动态分配模型。
- **企业内部工具**：在控制预算的同时，为关键任务保留更高质量的推理能力。
